### 1-2. 자동 발행이 지금 동작하지 않는 이유 (런북 §1 요약)

- `JobQueue.registerProcessor()` 호출이 0건이다. 큐에 넣어도 소비하는 곳이 없다(`src/scheduler/JobQueue.ts`).
- 기본 스케줄 잡은 `tistory` 대상이고 `maxPostsPerRun: 5`라서 네이버 운영 정책(1회 1건)과 맞지 않는다(`config/default.yaml` `scheduler.jobs`).
- "자동 포스팅 설정" 화면(`src/web/client/src/pages/Scheduler.tsx`)은 이 동작하지 않는 잡을 켜고 끄는 화면이다.
- 런북 §3의 launchd + 에이전트 CLI 트리거는 문서만 있고 로드되지 않았다.

→ 기존 스케줄러를 켜는 방식은 쓰지 않는다. **로봇은 새 모듈로 만들고, 기존 CronScheduler/JobQueue의 tistory 잡은 계속 비활성으로 둔다.**

## 2. 목표 구조

```
[robot 프로세스] ──HTTP(JWT)──▶ [web 서버 API] ──Playwright──▶ 네이버 실제 편집기(발행)
      │                               │
      │                               ├─ 광고 인벤토리 · 초안 · 발행 기록
      │                               └─ 네이버 브라우저 프로필 단독 소유
      │
      ├──익명 브라우저──▶ 발행된 글 (PC · 모바일 · 비로그인 · 광고 검증)
      └──SQLite(robot_runs / robot_commands)◀── 대시보드 "자동 포스팅" 화면(상태 조회·승인)
```

### 역할 분리

| 구분            | web 서버 (기존, 최소 변경)                  | robot (신규)                                                                         |
| --------------- | ------------------------------------------- | ------------------------------------------------------------------------------------ |
| 실행            | PM2 `blog-auto-poster-web`                  | PM2 `blog-auto-poster-robot`                                                         |
| 네이버 브라우저 | **단독 소유**. 발행 뮤텍스로 동시 발행 차단 | 직접 열지 않는다. 운영 프로필은 두 프로세스가 동시에 열면 잠금 충돌·세션 손상이 난다 |
| 상태 변경       | 초안 저장, 광고 배치, 발행                  | API 호출로만 요청한다                                                                |
| 판단            | 없음(결정적 변환만)                         | 주제 선정, 편집, 이미지·광고 적합성(LLM) + 코드 게이트                               |
| 스케줄          | 없음(`scheduler.enabled: false` 유지)       | 자체 cron, 주 2회, 상한 주 3회                                                       |
| 기록            | `published_posts`                           | `robot_runs`, `data/ops/runs/<runId>/`, `data/ops/publish-log.jsonl`(스킬 §10 규약)  |

> **주의**: 로봇을 가동하면 런북 §3의 launchd 트리거는 **로드하지 않는다**. 둘이 함께 돌면 같은 창에 두 번 발행한다.

## 3. 쿠팡 파트너스 광고 설계

### 3-1. 광고 소재 확보 (2단계)

| 단계                       | 소스                                                                                                                             | 저장                                   | 비고                                                                                                                               |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **Track 1 — 지금(미승인)** | **반자동**(§3-1-1): 로봇이 주제별 "소재 요청"을 만들고, 사람이 파트너스 링크 생성 페이지에서 링크를 만들어 대시보드에 붙여넣는다 | `ad_inventory` 테이블(source=`manual`) | 최종 승인 전에도 링크 수익은 발생하고, 최종 승인 조건(누적 판매)은 이 경로로 채워야 한다                                           |
| **Track 2 — 최종 승인 후** | Open API 상품 검색(키워드, 최대 10개) + 딥링크 변환                                                                              | `ad_inventory`(source=`api`, 24h 만료) | 검색 **시간당 10회** 제한. 한도 초과 403이 누적되면 계정 API가 제한될 수 있다는 보고가 있으므로 코드로 예산을 강제한다(§5 Phase 4) |
| 쓰지 않음                  | 파트너스 다이나믹/캐러셀 위젯                                                                                                    | —                                      | 주제와 무관한 상품이 나온다(이슈 #21)                                                                                              |
| 쓰지 않음                  | 로봇이 partners.coupang.com 화면을 자동 조작해 링크 생성                                                                         | —                                      | 아래 근거로 채택하지 않는다                                                                                                        |

**파트너스 화면 자동 조작을 쓰지 않는 근거**

1. **쿠팡이 자동 접속을 막고 있다(실측)**: 2026-09-15 헤드리스 Playwright로 `partners.coupang.com/#affiliate/ws/link`에 접속하자 Akamai 엣지가 `Access Denied`를 반환했다(로그인 이전 단계). 자동화하려면 봇 탐지를 우회해야 하는데, 이는 구현하지 않는다.
2. **계정 제재 위험이 수익 구조 전체를 건다**: 파트너스는 부정 행위로 판정하면 최근 30일 수익 몰수와 계정 해지를 통보한 사례가 있다. 최종 승인 전에 계정이 해지되면 API 경로(Track 2)까지 사라진다.
3. **로그인 자동화 금지**: 스킬 §0이 네이버에 대해 정한 원칙("로그인은 사람이 한다")과 같다. 파트너스 계정 비밀번호·2단계 인증을 로봇에 맡기지 않는다.
4. 파트너스 이용약관 원문의 자동화 조항은 이 문서 작성 시점에 직접 확인하지 못했다(사이트가 자동 조회를 차단하고, 이용 가이드 PDF는 이미지 기반). 로그인한 브라우저에서 이용약관·운영정책을 확인해 이 절에 조항 번호를 채운다.

#### 3-1-1. API 없이 소재를 채우는 반자동 흐름

사람이 하는 일은 "쿠팡 파트너스에서 링크 만들기 → 대시보드에 붙여넣기" 하나로 줄인다. 주제 찾기, 필요 수량 계산, 상품명·이미지 추출, 배치, 검증은 로봇과 대시보드가 맡는다.

| 순서 | 주체     | 내용                                                                                                                                                                                                                         |
| ---- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 로봇     | **기획 실행**(발행 1–2일 전, §4-2)에서 주제를 고르고, 소재가 `minAds`보다 부족하면 `ad_requests` 행을 만든다: 키워드, 카테고리, 필요 수량, 발행 예정 시각, 상품 선정 기준(글의 체크리스트 요약), 쿠팡 검색 결과 바로가기 URL |
| 2    | 대시보드 | 알림(WebSocket·macOS) + "쿠팡 현황 > 소재 요청" 카드. 카드에 파트너스 링크 생성 페이지 바로가기와 붙여넣기 칸 N개를 표시한다                                                                                                 |
| 3    | 사람     | 본인 브라우저에서 파트너스 링크 생성 페이지를 열어 상품을 고르고 링크를 만든 뒤, 결과(이미지 포함 HTML 또는 단축 URL)를 칸에 붙여넣는다. 요청 1건에 상품 2–3개, 약 3–5분 예상                                                |
| 4    | 대시보드 | 기존 `parseLinkInput`(`src/content/linkInput.ts:61`)이 붙여넣은 HTML에서 링크·이미지·상품명(alt)을 뽑아 채운다. 키워드·카테고리는 요청에서 자동 입력한다. 저장 즉시 링크 생존을 확인한다(쿠팡 상품 페이지 도착)              |
| 5    | 로봇     | **발행 실행**에서 소재가 `minAds` 이상이면 진행하고, 부족하면 `skipped-no-ads`로 끝낸 뒤 주제를 다음 기획으로 넘긴다. 억지로 무관한 상품을 넣지 않는다                                                                       |

- **미리 채워 두기**: 발행 대상 카테고리별로 소재 5–10개를 한 번에 등록해 두면 대부분의 사이클은 요청 없이 진행된다. 요청은 새 주제가 나올 때만 생긴다.
- **로봇이 쿠팡 페이지를 대신 열지 않는다**: 검색 바로가기는 사람이 클릭하는 링크일 뿐이다. 로봇은 coupang.com·partners.coupang.com을 조회하지 않는다. 링크 생존 확인은 등록된 단축 링크 1건을 저빈도(7일 1회)로 요청하는 수준으로 제한한다.
- **자기 클릭 금지**: 링크 생존 확인은 리다이렉트 헤더까지만 보고 구매 흐름에 들어가지 않는다. 사람도 자기 링크로 구매하지 않는다(파트너스 금지 행위).

`ad_inventory` 스키마(초안, `data/blog-auto-poster.db`):

```sql
CREATE TABLE ad_inventory (
  id TEXT PRIMARY KEY,
  source TEXT NOT NULL,             -- manual | api
  product_name TEXT NOT NULL,
  url TEXT NOT NULL,                -- 파트너스 트래킹 링크 (link.coupang.com/a/… 또는 API productUrl)
  image_url TEXT,                   -- 발행 시 네이버로 리호스팅 (rehostRemoteImages)
  keywords TEXT NOT NULL,           -- JSON 배열, 표기 변형 포함 ("트위드자켓","트위드 자켓")
  category_id TEXT,                 -- 네이버 쇼핑 cat_id (ShoppingCategoryStore와 같은 코드)
  price_snapshot INTEGER,           -- 참고용. 기본적으로 본문에 노출하지 않는다
  status TEXT NOT NULL DEFAULT 'active',  -- active | dead | expired
  last_checked_at TEXT,             -- 링크 200/랜딩 확인 시각
  expires_at TEXT,                  -- api 소스만
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

기존 `data/link-presets.json`(현재 없음)과 `LinkPresetStore`는 이 테이블로 흡수한다. 이벤트·배너 프리셋은 `kind` 컬럼을 추가해서 함께 관리한다.

### 3-2. 관련성 매칭 (주제와 맞는 광고만)

순수 함수 `matchAds({ keyword, categoryPath }, inventory) → RankedAd[]` (`src/content/AdMatcher.ts`):

1. **키워드 일치**(공백·대소문자 정규화 후 `keywords` 포함) → 1순위
2. **카테고리 일치**(글의 cat_id 또는 조상 cat_id) → 2순위
3. 둘 다 아니면 **제외**. 무관한 상품으로 자리를 채우지 않는다(#21 교훈)
4. `status != active` 또는 `last_checked_at`이 7일보다 오래된 소재는 발행 전에 링크를 재확인한 뒤에만 쓴다
5. 같은 글 안에서 같은 상품은 한 번만 쓴다

**주제 선정과 연결**: 광고가 목적이므로 관련 광고가 `minAds`(기본 2)개 미만인 후보 주제는 탈락시킨다. 런북의 수요 기준을 통과한 후보 중 **광고 소재가 있는 주제**만 고른다. 통과 후보가 없으면 `skipped-no-ads`로 끝내고, 대시보드에 "이 카테고리 소재 등록 필요"를 표시한다.

### 3-4. 광고 블록 형식

- 네이버 발행에서 살아남는 것이 실측된 **인라인 스타일 상품 카드**(`buildProductPreviewCard`, `src/content/CoupangPreview.ts:227`)를 쓴다. iframe/script는 쓰지 않는다(네이버가 100% 제거, #20).
- 카드 구성: 상품 이미지(링크) · 상품명(링크) · "🛒 쿠팡에서 보기" 버튼. 링크는 모두 `rel="nofollow sponsored"`, 새 창.
- **가격은 기본적으로 표시하지 않는다.** 가격은 수시로 바뀌고 발행 후 수정할 수단이 없다(스킬 §0). 표시하려면 "조회 시점 기준, 변동 가능" 문구와 조회 시각을 함께 넣는다(`policy.showPrice`).
- 평점·리뷰 수는 API 원천 값이 있을 때만 표시한다. 추정하거나 지어내지 않는다.
- 상품 이미지는 `rehostRemoteImages=true`로 네이버에 올린다(쿠팡 CDN 차단 환경 대응, 런북 리스크 7).

## 4. 로봇 설계

### 4-1. 실행 형태

- 엔트리: `src/robot/index.ts` → `dist/robot/index.js`. PM2 `ecosystem.config.cjs`에 web·robot 두 앱을 정의한다.
- 단일 인스턴스: SQLite 리스(`robot_state.lease`, 만료 시각 갱신)를 쓴다. 두 번째 인스턴스는 즉시 종료한다.
- 스케줄: cron 대신 주간 슬롯 목록 + 60초 틱 + 놓친 슬롯 보정(설계서 §5-6). 설정 `robot.enabled: false`가 기본이다.
- CLI: `npm run robot -- once --kind publish --until GATE`(발행 직전까지만, 드라이런) / `once` / `status` / `doctor`(설계서 §7-3).
- macOS 운영: `pm2 startup` + `pm2 save`, 슬롯 5분 전 깨우기(`sudo pmset repeat wakeorpoweron MTRS 20:55:00`), 사용자 로그인 세션 유지(설계서 §7-1).

### 4-2. 사이클 상태 머신

각 단계는 시작 전에 `robot_runs.step`을 영속화하고, 끝나면 결과를 `robot_steps`와 `data/ops/runs/<runId>/`에 기록한다. 괄호는 스킬 단계 번호다.

API가 없는 동안(Track 1)은 사이클을 **기획 실행**과 **발행 실행** 두 번으로 나눈다. 사람이 소재를 채울 시간을 벌기 위해서다.

- **기획 실행**(월·목 21:00): `PREFLIGHT` → `SNAPSHOT_LIVE` → `RESEARCH` → `SELECT_TOPIC` → `REQUEST_ADS` → `PLANNED`
- **발행 실행**(화·토 21:10): `PREFLIGHT` → `RESOLVE_ADS` → `SNAPSHOT_LIVE`(중복 재확인) → `GENERATE` → … → `RECORD`
- 최종 승인 후 API로 소재를 즉시 확보할 수 있게 되면 두 실행을 하나로 합친다.

| 단계             | 성격       | 내용                                                                                                                                                            | 실패 시                            |
| ---------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| `PREFLIGHT`      | 코드       | `/health`, 네이버 세션 만료(14일 규칙), 이미지 예산, 대시보드 로그인, 주기 상한(주 3회), 직전 발행 카테고리 (S0)                                                | `aborted-<reason>`                 |
| `SNAPSHOT_LIVE`  | 코드       | RSS·PostList 스냅샷, 중복 윈도우 180/365일 대상 목록 (S1)                                                                                                       | abort                              |
| `RESEARCH`       | 코드       | 카테고리 인기검색어, 검색어트렌드, 클릭지수, 문서량 조회 (S2–S4)                                                                                                | abort (추정치로 대체 금지)         |
| `SELECT_TOPIC`   | LLM + 코드 | 코드가 상승 4주·포화도·중복·연속 카테고리로 1차 필터(소재가 이미 있는 주제에 가점) → LLM이 "경험 없이 기준형으로 쓸 수 있나"를 판정하고 `decision.md` 작성 (S5) | 후보 0 → `skipped-no-candidate`    |
| `REQUEST_ADS`    | 코드       | 기획 실행 전용. 선정 주제의 §3-2 매칭 결과가 `minAds` 미만이면 `ad_requests` 생성 + 알림(§3-1-1)                                                                | —                                  |
| `RESOLVE_ADS`    | 코드       | 발행 실행 첫 단계. 계획된 주제의 소재가 `minAds` 이상인지 확인하고 7일 넘은 링크는 재확인                                                                       | 미달 → `skipped-no-ads`(주제 이월) |
| `GENERATE`       | 코드       | `POST /api/posts/generate-from-keyword` → `generationStatus` 폴링 (S6)                                                                                          | `aborted-llm`                      |
| `EDIT`           | LLM + 코드 | 1인칭·근거 없는 수치 제거 재작성, 링크 200 확인, 이미지 손상(디코드)·섹션 적합성(비전 판정, 불확실하면 제외) → `PUT /api/posts/:id` (S7–S9)                     | 게이트 3회 실패 → abort            |
| `PLACE_ADS`      | 코드       | `POST /api/posts/:id/place-ads`(신규) → 초안에 광고 마커·고지 저장                                                                                              | abort                              |
| `GATE`           | 코드       | 구조 게이트(런북 백로그 ④) + `AdGate` + 금지어 → `publish-preview.html` sha256 기록 (S10)                                                                       | abort (발행 안 함)                 |
| `AWAIT_APPROVAL` | 사람       | 수동 모드만 해당. 대시보드에 미리보기·결정 근거·광고 목록 표시, 승인/거절 대기(최대 2시간)                                                                      | 시간 초과 → `aborted-no-approval`  |
| `PUBLISHING`     | 코드(1회)  | `POST /api/posts/:id/publish {platform:"naver", visibility:"public", aiPolish:false}` (S11)                                                                     | **재호출 금지** → `RECONCILE`      |

### 4-3. 판단 단계 원칙

- LLM 출력은 **구조화 JSON**으로 받고, 합격 여부는 LLM이 아니라 코드 게이트가 결정한다(런북 §2 "판단은 에이전트, 게이트는 코드").
- LLM 설정은 기존 대시보드 설정(`resolveLlmConfigFromConfigManager`)을 그대로 쓴다. 로봇 전용 키를 따로 두지 않는다.
- 스킬의 금지 목록·통과 기준을 `src/robot/policies.ts` 상수로 옮기고, 스킬 문서는 이 상수를 참조하게 바꾼다(규칙의 단일 출처를 코드로).
- 템플릿 기본 필드의 1인칭 체험 문구(`src/content/KeywordPostGenerator.ts:36` 등)를 기준형 문구로 바꾼다. 매 사이클 LLM이 지우는 방식에 의존하지 않는다.

### 4-4. 멱등성·중복 발행 방지

| 위험                  | 방어                                                                                                                                      |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 발행 도중 로봇 재시작 | `step=PUBLISHING`으로 재시작하면 publish를 **절대 다시 호출하지 않고** `RECONCILE`로 간다                                                 |
| 발행 HTTP 타임아웃    | 타임아웃 10분. 초과하면 재호출하지 않고 `RECONCILE`                                                                                       |
| web 서버 측 동시 발행 | publish 라우트에 프로세스 내 뮤텍스를 두고, 같은 `draftId`/제목을 24h 안에 다시 발행하면 409(런북 백로그 ①)                               |
| 라이브 제목 중복      | `adapter.createPost` 직전에 RSS 제목을 대조하고 중복이면 409(백로그 ③)                                                                    |
| 검증과 발행본 불일치  | 로봇 요청은 `aiPolish:false` 필수(백로그 ②). 광고 배치는 초안 단계에서 끝내고, publish 라우트는 robot 요청에 대해 자동 배치를 하지 않는다 |
| 세션 만료             | `/health`에 `naver.sessionExpiresAt` 노출(백로그 ⑤), PREFLIGHT에서 14일 미만이면 중단하고 알림                                            |

### 4-7. 대시보드 연동 (최소 변경)

- "자동 포스팅 설정" 화면(`Scheduler.tsx`)의 동작하지 않는 잡 목록을 **로봇 패널**로 바꾼다: 활성/일시정지, 모드, 다음 실행 시각, 진행 중 단계, 승인 대기 초안(미리보기·결정 근거·광고 목록·승인/거절), 최근 실행 10건(결과·URL·경고).
- "쿠팡 현황" 화면에 **광고 소재 관리**를 추가한다: 등록(링크·상품명·키워드·카테고리), 링크 상태 재확인, 카테고리별 소재 수("소재 부족" 표시), **소재 요청 카드**(§3-1-1: 파트너스 링크 생성 페이지 바로가기, 붙여넣기 칸, 발행 예정 시각까지 남은 시간).
- 통신: web은 `robot_runs`를 읽기만 하고, 명령은 `robot_commands` 행으로 넣는다(로봇이 10초 주기로 폴링). 로봇에 별도 포트를 열지 않는다.
- API: `GET /api/robot/status`, `POST /api/robot/commands`, `GET|POST|PATCH|DELETE /api/ads/inventory`, `POST /api/ads/inventory/:id/check`, `POST /api/posts/:id/place-ads`.

### 4-8. 알림

`AWAIT_APPROVAL` 진입, `aborted-*`, `published-with-warnings`, 세션 만료 임박 시 알린다. 대시보드 WebSocket 알림(기존 `WebSocketContext`)과 macOS 알림을 기본으로 하고, 외부 채널(Slack·텔레그램)은 선택이다.

2. **광고 밀도**: 블록 2–4개(권장) / 더 많이
3. ~~쿠팡 파트너스 최종 승인·API 키 현황~~ → **미승인 확인(2026-09-15)**. Track 1 반자동으로 진행하고, 최종 승인 후 Phase 4를 시작한다
